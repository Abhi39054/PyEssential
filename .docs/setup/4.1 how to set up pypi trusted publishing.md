# How to Set Up PyPI Trusted Publishing

PyEssential publishes to PyPI and TestPyPI using **Trusted Publishing**. GitHub Actions
proves its identity to PyPI with a short-lived OpenID Connect (OIDC) token, so **no API
tokens or passwords are stored** in the repository.

## Why use it

- **No long-lived secrets.** Nothing to leak, rotate, or revoke by hand.
- **Scoped access.** Only the registered repository, workflow file, and environment can upload.
- **Easy to verify.** Each uploaded file shows *Uploaded using Trusted Publishing? Yes* on PyPI.

## How it works

1. A tag such as `v0.1.6` is pushed and the workflow runs.
2. A publish job asks GitHub for an OIDC token (this needs the `id-token: write` permission).
3. `pypa/gh-action-pypi-publish` sends the token to PyPI.
4. PyPI checks that the token's repository, workflow filename, and environment match a
   registered *trusted publisher*, then issues a temporary upload credential.

## Values used in this project

| Setting | PyPI | TestPyPI |
|---------|------|----------|
| Owner | `Abhi39054` | `Abhi39054` |
| Repository | `PyEssential` | `PyEssential` |
| Workflow name | `pypi-publish.yaml` | `pypi-publish.yaml` |
| Environment | `pypi-prod` | `testpypi` |

These values must match the repository, the workflow file name, and the GitHub environment
names **exactly** (including capitalization).

## Setup steps

### 1. Register the publisher on PyPI

1. Sign in at https://pypi.org and open the project.
2. Go to **Manage → Publishing** (the project's *Settings → Publishing* page).
3. Under **Add a new publisher**, choose **GitHub** and fill in the values from the table above.
4. Click **Add**.

> **Brand-new project that is not on PyPI yet?** Use a *pending publisher* instead, from your
> account's Publishing page (https://pypi.org/manage/account/publishing/). The project is
> created the first time the workflow publishes.

### 2. Register the publisher on TestPyPI

Repeat step 1 on https://test.pypi.org with the TestPyPI values (environment `testpypi`).
TestPyPI is a separate service with its own accounts, projects, and publisher settings.

### 3. Create the GitHub environments

In the repository, go to **Settings → Environments → New environment** and create:

| Environment | Protection rules |
|-------------|------------------|
| `testpypi` | None |
| `pypi-prod` | **Required reviewers** (you), so every PyPI release needs manual approval |

If an environment is restricted to selected branches or tags, allow the tag pattern `v*`.

> **Names must agree.** If a publisher on PyPI has an environment configured, the workflow job
> must use that same environment. If the environment field was left blank on PyPI, the job
> must not set one.

### 4. Configure the workflow

In `.github/workflows/pypi-publish.yaml`, each publish job needs:

- `permissions: id-token: write`
- an `environment` matching the one registered on PyPI
- **no** `user` or `password` inputs

```yaml
  pypi_test_publish:
    name: 🚀 Publish to TestPyPI
    needs: build_sdist_wheel
    runs-on: ubuntu-latest
    if: startsWith(github.ref, 'refs/tags/v')

    environment:
      name: testpypi
      url: https://test.pypi.org/project/pyessential/

    permissions:
      id-token: write

    steps:
      - uses: actions/download-artifact@v4
        with:
          name: python-distribution-files
          path: dist/

      - uses: pypa/gh-action-pypi-publish@release/v1
        with:
          repository-url: https://test.pypi.org/legacy/
          packages-dir: dist/
          skip-existing: true

  pypi_publish:
    name: 🚀 Publish to PyPI (Requires Approval)
    needs: pypi_test_publish
    runs-on: ubuntu-latest
    if: startsWith(github.ref, 'refs/tags/v')

    environment:
      name: pypi-prod
      url: https://pypi.org/project/pyessential/

    permissions:
      id-token: write

    steps:
      - uses: actions/download-artifact@v4
        with:
          name: python-distribution-files
          path: dist/

      - uses: pypa/gh-action-pypi-publish@release/v1
        with:
          packages-dir: dist/
```

Job-level `permissions` replace the workflow-level ones, so a job that needs other
permissions (for example `contents: write` for creating a GitHub Release) must list them itself.

### 5. Release and verify

1. Push a version tag (see `6. How to release a new version.md`).
2. The TestPyPI job publishes automatically. The PyPI job waits for your approval under
   **Review deployments**.
3. On PyPI, open the new version's **Download files** tab, expand a file's *view details*
   panel, and check that it says **Uploaded using Trusted Publishing? Yes**.

### 6. Remove old API tokens

Only after one release has succeeded with Trusted Publishing:

1. Delete the `PYPI_API_TOKEN` and `TESTPYPI_API_TOKEN` repository secrets
   (*Settings → Secrets and variables → Actions*).
2. Revoke the matching API tokens in your PyPI and TestPyPI account settings
   (*Account settings → API tokens*). Deleting the secret alone does not disable the token.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|--------------|-----|
| `invalid-publisher` error | Owner, repository, workflow name, or environment sent by GitHub does not match the publisher on PyPI | Compare the values printed in the job log with the publisher settings. Fix whichever side is wrong. |
| Error about missing OIDC token or `ACTIONS_ID_TOKEN_REQUEST_URL` | The job lacks `id-token: write` | Add `permissions: id-token: write` to the publish job. |
| Workflow name mismatch | Registered `pypi-publish.yml` but the file is `pypi-publish.yaml` (or the reverse) | Re-register the publisher with the exact file name. |
| Environment mismatch | Publisher has an environment but the job has none, or the names differ | Use the same environment name on both sides. |
| Job is stuck *Waiting* | `pypi-prod` requires approval | Open the run and click **Review deployments**. |
| Upload fails with *File already exists* | The version was already published (PyPI never allows re-uploading a version) | Bump the version and release again. |
| Publisher stopped working after renaming the repo or workflow | Registered values are now stale | Remove the old publisher and add a new one with the current names. |

PyPI does not support reusable workflows as the trusted workflow, so the publish jobs must live
in the workflow file that is registered.

## Using this in another project

1. Register a publisher on PyPI (or a *pending publisher* for a new project) with that
   repository's owner, name, workflow file, and environment.
2. Create the matching GitHub environment.
3. Give the publish job `id-token: write` and the same `environment`.
4. Use `pypa/gh-action-pypi-publish@release/v1` without `user` or `password`.
